Every time I sit down with a customer to review their Copilot Studio rollout, the same question shows up around minute ten: "Which agent is burning our Copilot Credits?" The Power Platform admin center answers that question, but only for the last 30 days, and only on screen. The moment someone asks for a quarter-over-quarter view, or an alert when an agent goes off the rails, we end up exporting, pasting and hoping nobody forgets to do it next month.

Microsoft just published a new tutorial on Microsoft Learn: Download Copilot Credit usage reports programmatically (preview). It shows how to use the Copilot Credit usage reports API, now in public preview, to submit, poll and download the same Copilot Credit entitlement and consumption data you see in the Power Platform admin center, and then act on the report rows. My take: this is the missing piece for agent FinOps, and the most interesting part is that you can run it from a workflow in Copilot Studio itself.

1. What really changes: the 30-day window stops being your history

The admin center reporting window is 30 days. The tutorial is explicit about the use cases: automate decisions, combine the data with other data sources, or maintain a long-term history beyond the 30-day reporting window. That last one is the big deal for me. Credit consumption is a trend question. You only see that an agent doubled its usage after a new knowledge source was added if you have the months before it.

With the API, you schedule a report, land the file wherever your organization keeps its data, and the history is yours. One detail to keep in mind from the docs: dates in the most recent 30 days can still change because of late data and corrections, so treat recent rows as provisional and refresh them.

2. The underrated detail: two reports, two different questions

There are two report types, and picking the right one matters more than it looks:

  • FeatureDetailsPerResource: consumption by agent (resource), environment, product and feature. Columns include ResourceName, EnvironmentName, Product, Feature, Channel, KnowledgeSources, ToolUsed, LLMModel, plus BilledCredits and NonBilledCredits.
  • BillingDetailsPerEnvironment: entitlement and consumption by environment, entitlement and billing policy, including prepaid and pay-as-you-go. Credit columns are CapacityPackCreditsConsumed and PayGoConsumedQuantity.

Both support Daily granularity (one row per day per dimension combination) or Summary (summed across the date range, no date column). The first report is what a maker or a CoE lead wants: which agent, which feature, which model. The second is what finance wants: how much of the capacity pack went where, and how much spilled into pay-as-you-go. Microsoft also notes that the two reports classify credits differently and may not reconcile, so don't build a dashboard that expects them to match to the last credit.

3. Three ways to get the data

The tutorial covers three clients, and I like that it doesn't force one:

  • Power Platform for Admins V2 connector, in Power Automate or in Copilot Studio workflows, with three actions: Generate Licensing Report, Get Licensing Report Operation Status and Download Licensing Report File.
  • Power Platform CLI: pac copilot-studio generate-licensing-report, pac copilot-studio get-licensing-report-operation and pac copilot-studio download-licensing-report-file.
  • PowerShell (REST), calling the Power Platform API directly.

The generation is asynchronous: submit, poll, then download. Generate returns 202 Accepted with Location and Retry-After headers, and the status call returns HTTP 200 even while the status is Running. If you have built long-running operations in Power Automate before, this pattern will feel familiar. If you haven't, the tutorial walks through the Do until loop step by step.

4. Risk and governance: read the preview fine print

This is where I slow customers down. According to the docs:

  • It is in public preview, not meant for production use, and sovereign clouds aren't currently supported.
  • Delegated (user) authentication only. Application-only (service principal) tokens aren't supported.
  • The user needs one of these roles: Global Administrator, Power Platform Administrator or Dynamics 365 Administrator.
  • Submissions can return 429 Too Many Requests. Honor Retry-After, schedule reports instead of looping, and reuse downloaded files.

Delegated auth with an admin role means the flow runs under a highly privileged identity. Own that connection deliberately: a named admin account, a dedicated environment for the flow, and a clear owner. Don't let it live in someone's personal default environment.

5. What admins and makers should do now

The tutorial includes a complete weekly flow, and it is a great starting point. Every Monday it reports on the previous 14 complete UTC days with FeatureDetailsPerResource and Summary, adds BilledCredits and NonBilledCredits, and sends an email (Office 365 Outlook) with an HTML table of the rows above a CreditThreshold of 1,000.

One subtlety worth knowing before you show this to your CFO: the threshold logic is per row, not per agent. Two rows of 600 credits for the same agent aren't selected by a 1,000 threshold. If you want a per-agent alert, group by ResourceID first.

My checklist for this week:

  • Pick the identity and environment that will own the Power Platform for Admins V2 connection.
  • Build the weekly flow from the tutorial, test the true branch with CreditThreshold set to 0, then restore it.
  • Start landing daily files in storage now, so your history starts growing today.
  • Agree with finance which report feeds which dashboard.

What I'm watching

The docs list two things coming in December 2026: a new connector action that combines submission, polling and download in one step for Power Automate and Copilot Studio, and JSON report format support through the connector (it currently defaults to CSV). That single action will remove most of the plumbing from the flow, and I expect it to make this pattern standard in every CoE starter setup.
